Startup currently opens the event store, loads and replays the corpus, and renders
before asynchronous identity checking. `/pair` hides the main element but still
replays. Logout ends the server session only; every local store and draft survives.
Peer messages refresh events/cursors, never lock. No unsafe HTML/eval rendering sink
was found in the household path.

JS writes all 17 canonical event variants. `event-store.js` validates and extracts
canonical headers, and `sync-coordinator.js` reads IDs and Lamport time at fixed
offsets (including 76). Rust already has native-testable replay, recurrence and
protocol decoding in one dependency-free `rlib`/`cdylib`; splitting crates is not
needed to establish portability.

## Frozen invariants

Locked means no intentionally retained household projection, decrypted event
corpus, usable household root/DEK/KEK, or protected command capability. A server
session cookie is not a local decryption key. Startup opens public security
metadata only; decrypt, validate and replay happen after a successful unlock.
Authentication/crypto errors leave the application locked with no partial replay.
Lock invalidates in-flight operations, clears UI and drafts, drops the WASM engine
and all key references, and broadcasts a content-free lock to peer tabs. This is
reference disposal, not a physical memory-zeroization guarantee.

The first encryption setup must establish and verify an independent, user-held
256-bit recovery secret. It is never sent to the relay or saved in browser storage.
It is an explicit authorized local unlock path, including on browsers lacking
PRF and when the process-local identity server has lost its state. Losing every
credential/recovery path loses the ciphertext permanently. Losing the browser
profile additionally requires an encrypted archive; a secret does not recreate
missing data. Do not permit removal of the final verified unlock path.

Use a random 256-bit household storage root with independently removable wrappers.
Derive purpose keys with HKDF-SHA-256 and explicit versioned context strings:
`kin/local-storage/v1`, `kin/local-wrapper/v1`, `kin/archive/v1`. Existing random
sync epoch keys remain separate; protect them under the local root without
changing relay envelopes. The root protects the shared local household corpus,
not one adult's personal subset. Adult credentials wrap the same root independently.
New installations may use different local roots while syncing the same canonical
household; sync membership and historical-epoch entitlements remain authoritative.

Credential wrappers use a verified WebAuthn assertion with required user
verification and a credential-specific PRF result, then HKDF; never derive from
the public assertion signature, credential ID, cookie, or biometric. Check actual
extension results, not only browser capability hints. Missing/cancelled PRF means
an explicit recovery path or an error, never plaintext persistence. PRF output
stays in the browser. See the [WebAuthn PRF specification](https://www.w3.org/TR/webauthn/#prf-extension).

## Encrypted storage and migration

Use AES-256-GCM with a fresh 96-bit CSPRNG nonce and a 128-bit tag for every
encryption. The implementation derives a one-use AES key with a fresh 256-bit HKDF
salt for each encryption, avoiding a reused root AES key and a counter that resets
on reload. Retries reuse committed ciphertext or generate fresh salt/nonce pairs.
AAD is an unambiguous encoded string-array contract binding purpose, envelope version, vault/household
context, store/record type, and stable record identity. Encrypt complete protected
values, including canonical outbox copies and sensitive metadata. Only minimal
key-path/index identifiers, format versions, ciphertext lengths and security
wrappers may remain outside. Validate routing fields against decrypted content.

Preserve current atomic event/context/outbox/cursor transactions. An encrypted
IndexedDB adapter must explicitly keep native transactions alive while Web Crypto
is pending, abort on any crypto/lock failure, and release the keepalive only after
all dependent requests finish. No asynchronous crypto in schema-upgrade callbacks.
Do not silently accept legacy rows once an encrypted manifest has committed.

Migration states distinguish unconfigured legacy data, preparing/verification,
cleanup pending, and encrypted. Persist verified recovery wrappers and a stable
vault ID before touching legacy data. Never generate a second root on restart
when a migration journal exists. Close old schema connections, exclude concurrent
writers, snapshot all protected stores, encrypt, decrypt back, compare exact
canonical bytes, and perform complete Rust replay before replacement commits.
Failure/cancellation/quota/abort preserves the original corpus or a verified
recoverable encrypted replacement. Cross-database progress is journalled, not
claimed to be one IndexedDB transaction. Mark encrypted only after both event
and key stores have committed and legacy capabilities have been removed.

Legacy nonextractable device private keys cannot be exported or wrapped. Merely
deleting local epoch wrappers while retaining ECDH is insufficient: old or future
relay provisioning packages could restore epoch keys. Migration must pre-sign a
bounded, domain-separated device-key successor certificate using the old signing
key; generate new transport keys, encrypt their private serialization under the
local root, then discard the old private CryptoKeys. Preserve old PUBLIC keys for
historical signatures/certificates. The server verifies expected old fingerprint,
identity, generation and signature, applies the transition idempotently, and purges
obsolete grants. Peers verify the signed chain from existing pins. A migration may
finish locally offline with this protected transition queued; network sync waits
for acceptance. Do not silently trust a changed directory fingerprint. Preserve
exact cached envelopes and event identity throughout.

Remove plaintext draft persistence. Drafts may remain in unlocked memory and must
be cleared on lock. Clear historical session draft keys before components mount;
other open tabs must lock/clear too. Previously loaded old-version pages and copied
plaintext cannot be recalled; migration requires closing/reloading those pages.

## Rust / browser boundary

Keep the manual WASM ABI and the existing dependency-free native crate. Rust owns
command validation and canonical event creation; canonical decode/validate/metadata;
version interpretation; recurrence; identity-aware deterministic replay; bounded
archive framing/validation and import planning. Browser context explicitly supplies
random IDs, wall/civil time and authorization identity. Coarse commands return
canonical bytes plus the resulting projection. Existing protocol v1–v8 bytes and
replay fixtures remain valid. JS must not read canonical field offsets outside
the narrow WASM adapter. Browser-specific identity/pairing and transport operations
remain separate from household domain commands.

JavaScript owns DOM/Web Components, WebAuthn, Web Crypto, IndexedDB, clocks/randomness,
networking, files/downloads, lifecycle/focus and platform accessibility. No Rust DOM,
service worker, framework, convenience WASM crate or dependency is required.

## Archive and offline boundary

Normal archives contain versioned metadata, recovery/root wrappers and authenticated
encrypted canonical history/protected metadata. Rust parses bounded framing and
rejects unsupported versions, malformed lengths, duplicates and trailing data.
Browser crypto authenticates/decrypts; Rust validates the entire canonical corpus
and plans import before any atomic replacement. Corruption must never partially
import. Recovery-wrapped archives are portable; credential-only wrappers may remain
origin/credential-bound. Import must not restore revoked device trust or silently
overwrite an existing household. No default plaintext export.

The service worker may cache an explicit static shell allowlist only. Never cache
API responses, projections, canonical plaintext, key material or user-specific
debug state. Offline startup always follows the same locked shell. Storage
persistence is a capability request, not a backup guarantee.

## v0.10.0 implementation and validation record

The implementation preserves the two governing boundaries: Rust owns all 17
household commands, canonical encode/decode/validation, metadata extraction,
identity-aware replay, recurrence, archive framing and import planning; JavaScript
retains DOM/accessibility, WebAuthn, Web Crypto, IndexedDB, networking, files,
clocks/randomness, lifecycle and service-worker capabilities. The dependency-free
single Rust `rlib`/`cdylib` remains directly native-testable; a workspace split did
not provide a concrete benefit.

Persistent household plaintext remaining after successful migration: none found.
Complete event, context, outbox, binding, sync-state, private device-key and epoch
values use authenticated local envelopes. Drafts are memory-only. Static shell
assets, minimal key paths/indexes, envelope sizes/versions, lock/migration state,
root wrappers, public verification keys and sync routing metadata remain visible.
Cookies retain authorization metadata but no household text. A legacy dataset is
explicitly unprotected until setup and migration complete.

The event database advances 2→3 and key database 3→4. Local envelope, KARC archive
and device-key successor formats begin at 1. Existing canonical event schemas,
protocols v1–v8 and sync envelope v1 remain byte-compatible. v0.9.3 clients cannot
open the upgraded local databases; downgrade is unsupported. Legacy migration
uses Web Locks, a stable journal and exact source comparison. It rejects orphaned
or divergent outbox copies, stages signed replacement transport keys, decrypts and
compares every protected value, performs full Rust replay, and removes old usable
CryptoKeys only after verified event-store commit. Interruption resumes at the
recorded phase; failure before commit preserves the source.

Recovery uses the required random 256-bit user-held secret. It is neither persisted
nor transmitted. Optional passkey unlock requires a server-verified WebAuthn
assertion with required user verification and actual 32-byte PRF output; it does
not silently degrade when unavailable. PRF unlock needs the identity service;
recovery unlock works offline. Wrapper changes use `configRevision` compare-and-set;
removal atomically advances the durable lock epoch. The final recovery wrapper
cannot be removed. A copied wrapper plus secret and plaintext previously obtained
by an authorized endpoint cannot be recalled. In-place local-root rotation is not
implemented.

Encrypted archives bind metadata as AAD, retain only recovery wrappers, and restore
exact canonical history into an independently keyed empty installation. Complete
validation precedes one atomic replacement. Restore creates fresh local actor/device
identity, remains writable locally and blocks sync reattachment; it does not revive
revoked trust or recover the process-memory server identity.

The final WASM is 220,893 raw bytes and 65,831 bytes at gzip level 9, versus
196,905/57,613 at the base commit: +23,988 raw (+12.18%) and +8,218 gzip (+14.26%).
On a same-process Node raw-ABI benchmark with 24-byte text and input/output copies,
mean instantiation was 0.891 ms versus 0.466 ms; median replay was 1.129 versus
1.094 ms for 1,000 events and 9.365 versus 9.237 ms for 10,000. These microbenchmarks
exclude storage, crypto and DOM.

Real Edge storage measurements used 10,000 events. Typical 35-byte text produced
1,470,000 canonical bytes: migration 4.324 s, unlock/decrypt 2.913 s and replay
30.1 ms. Maximum 4,096-byte text produced 42,080,000 canonical bytes: migration
26.166 s, unlock/decrypt 18.450 s and replay 147.3 ms. Its encrypted archive was
60,209,420 bytes (57.42 MiB, 6,899,444 bytes below the 64 MiB limit), exported in
18.012 s and restored under an independent root in 24.719 s; every byte of all
10,000 canonical records matched. Peak observed Edge renderer working set was
about 1.26 GiB. Maximum-history latency and memory require v0.10 performance work
before claiming mobile suitability; typical histories remain the relevant current
prototype path.
